# 거리 사다리 결과 정리 — `S45B` (2026-09-03)

> **한 줄**: 검정 flange · randomization 켜고 · FOUP 1개 씬에서 **6거리 × 50프레임**을 배포 팔 `RH1` 로 돌렸다.
> **pose 는 0.40m 이상에서 무결점**이고, KPI 를 깎는 것은 **분할 오선택 17건(5.7%)뿐**이며

⚠️ 표의 «실측 중앙» 이 설정값과 몇 mm 다른 것은 **거리도 ±3cm 로 randomize** 하기 때문이다(의도된 설계).
채점 도구가 디렉토리 이름을 안 믿고 **GT 로 다시 재서** 그 값을 쓴다.

## 2. 오선택 17건 — 원인 분석

### 2.1 「오선택」이 정확히 무엇인가

SAM3 는 마스크를 **하나** 주지 않고 **후보를 10~42개** 준다. 그중 하나를 골라야 하는데,
**그 고르는 코드가 우리 것**이다 — `contracts.py:200 select_index()` (`segment_sam3.py:216` 이 호출).

```
SAM3 → [마스크₀ score₀ … 마스크ₙ scoreₙ]  →  🔴 select_index()  →  mask_full.png  →  FoundationPose
                                                (우리 코드)
```

🟢 **두 upstream 이 각자 «내 밖» 이라고 명시한 자리다** —
SAM3 §2 는 PCS 를 *"모든 인스턴스를 검출·분할"* 로 정의하고(고르는 건 출력이 아니다),
FoundationPose §5.4 는 *"외부 2D 검출에 의존하며 잘못된 검출이 자주 병목"* 이라고 적는다.

### 2.2 우리 규칙 3단과, 어디서 깨졌나

```
① 점수 게이트   score ≥ score_frac(0.9) × 최고점
② 면적 필터     area  ≥ min_area_frac(0.3) × (통과분 중 최대)
③ 중앙 근접     남은 것 중 화면 중심에 가까운 것
```

| 깨진 단계 | 건수 | 무슨 일 |
|---|:-:|---|
| **① 점수 게이트** | **16** | 정답 `score ÷ 최고 score` 가 **중앙 0.746** → 0.9 문턱에 걸려 **먼저 지워졌다.** ②③은 실행조차 안 된다 |
| **② 면적 필터** | **1** | `050/frame_0024` — 정답이 **최고 점수(0.727)에 IoU 0.979** 인데, 3.7배 큰 오검출이 문턱을 **159,221** 로 올려 정답(142,175)이 잘렸다 |
| ③ 중앙 근접 | 0 | — |
| **SAM3 자체** | **0** | 🔴 **정답 마스크는 17/17 전부 후보에 있었다** |

★ **즉 «분할이 틀린» 것이 아니라 «우리가 고르기를 틀린» 것**이다.

### 2.3 가림·잘림은 원인이 아니다

| 지표 | 오선택 프레임 | 정상 프레임 |
|---|--:|--:|
| GT 마스크 면적비 (그 거리 중앙 대비) | 중앙 **0.95** | p10~p90 **0.86~1.17** |
| 화면 잘림 | **3/17** | — |
| precision (고른 것 중 타깃 비율) | **0.000** (16/17) | — |

→ **FOUP 이 온전히 보이는데 «전혀 다른 물체» 를 골랐다.**

### 2.4 🔴🔴 오선택이 **항상 pose 실패로 이어지지는 않는다** — 17건 중 **6건은 회복**된다

| 오선택 프레임의 최종 결과 | 건수 |
|---|:-:|
| pose 도 실패 (KPI ❌) | **11** |
| ✅ **pose 는 정상** (KPI ✅) | **6** |

**기전 — crop 이 물체보다 훨씬 크기 때문이다.** stage1 의 crop 은
`mesh_diameter × crop_ratio = 579.0 × 1.2 = 694.8mm` 폭(반지름 **347.4mm**)이라,
초기 t 가 수백 mm 틀려도 **진짜 FOUP 이 아직 crop 안에 남아 있으면** render-and-compare 가 찾아낸다.

**예측을 세워 검증했다** — *"초기 t 오차가 crop 반지름(347.4mm)을 넘으면 회복 불가여야 한다"*:

| 초기 t 오차 | 건수 | KPI 통과 |
|---|:-:|:-:|
| **≥ 347.4mm** (진짜 물체가 crop 밖) | 5 | 🔴 **0건 (0%)** |
| **< 347.4mm** (crop 안에 남아 있다) | 12 | ✅ **6건 (50%)** |

★ **crop 안에 남는 것은 «필요조건이지 충분조건이 아니다»** — 넘으면 100% 실패하고,
안 넘어도 절반만 산다(나머지는 240개 가설의 채점이 엉뚱한 곳에서 수렴한다).

⚠️ **그래서 «오선택률» 과 «KPI 손실» 은 다른 수다** — 이 사다리에서 오선택은 17건인데
KPI 를 실제로 깎은 것은 **11건**이다. 표의 `KPI(전체)` 는 그 11건만 반영한다.

### 2.5 어떤 규칙이 몇 개를 되찾나 (17건에 재적용)

| 규칙 | 되찾은 수 |
|---|:-:|
| 현행 `center + score_frac 0.9` | **0/17** |
| **`center + score_frac 0.3`** | ✅ **15/17** |
| `center + 0.3 + min_area_frac 0.05` | 🔴 **2/17** (오히려 나쁨 — 작은 잡동사니가 살아남는다) |
| `score` 단독 | 1/17 |

🔴 **`score_frac` 만 낮추는 게 맞다** — 면적 필터를 같이 풀면 더 나빠진다.
🔴 **면적 필터 건(②)은 `score_frac` 으로 안 고쳐진다** — 별개 축이다.
⚠️ **기본값은 0.9 로 유지 중**이다(사용자 방침 — 실물에서 검증 후 결정).

## 4. 「frame → depth → mask → pose」 한 장 시트

`diag/*/diag_frame_XXXX.png` 가 **6패널을 인과 순서로** 담는다:

```
① 원본 left.png
② depth (스테레오 raw, 전 화면)
③ mask_full  (SAM3)        → stage1 이 씀
④ mask_flange (stage1 pose → CAD 투영)  → stage2 가 씀
⑤ stage2 가 실제로 먹는 depth (flange 밖은 0)
⑥ 최종 pose = RH1
```

🔴 **④는 «분할 산출물이 아니다»** — `top_flange.ply` 를 stage1 pose 로 투영한 것이라 SAM3 가 관여하지 않는다.
⚠️ ②는 자르지 않은 **전 화면 raw depth** 이고 **색 구간만** 물체 마스크에서 잡는다(배경이 포화돼 잘린 듯 보인다).
반면 ⑤는 **진짜로 가려진 데이터**다.

### 다시 만들기

```bash
cd <ws>/src/vision && source envs/env.sh
D=060
envs/pose/bin/python -m spatial_vision.viz.diag_sheet \
    --in runs/S45B_$D --seg-full runs/S45B_${D}_seg --depth-dir runs/S45B_${D}_st \
    --pose-dir runs/S45B_${D}_hyb1 --pose-name pose_coarse.json \
    --flange-name mask_flange_proj.png --seg-flange runs/S45B_${D}_p1 \
    --obj assets/obj/foup_300_semi_r2 --order pipeline --panel5 stage2 \
    --frames 3 --out <출력디렉토리>
```

오선택 프레임에서 **«SAM3 후보 전부와 어느 단계가 정답을 버렸는지»** 를 보려면:

```bash
envs/seg_sam3/bin/python tools/why_misselect.py --in runs/S45B_040 \
    --pick frame_0015,frame_0016 --prompt "cube shaped sealed plastic wafer pod" \
    --out <출력>.png
```
