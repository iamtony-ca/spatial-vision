## ⚠️ 1.5 Min-Z 는 우리에게 적용되지 않는다 (초판 오판 — 사용자 지적)

초판은 D455(520mm)·ZED X 4.6mm 를 **Min-Z 로** 근접 단계에서 제외했다. **틀렸다.**
Min-Z 는 물리 한계가 아니라 **D4 ASIC 의 시차 탐색 한계(126)** 를 거리로 환산한 값이다:

| @1280×720 | Min-Z | 그 거리의 시차 `fx·B/Z` |
|---|---|---|
| D405 | 100mm | 640×18/100 = **115px** |
| D435 | 280mm | 640×50/280 = **114px** |
| D455 | 520mm | 640×95/520 = **117px** |

셋 다 ~115px 로 수렴한다. **우리는 그 ASIC 을 안 쓴다** — 원시 L/R 을 FoundationStereo 에 넣는다.
실제로 `runs/zx_near` 는 **최대 시차 412px(중앙), 725px(최대)** 를 정상 처리했다.

**대신 남는 진짜 제약은 초점(DoF)** 이다. `H = f²/(N·c)`, `c = 1.5px × 3µm = 4.5µm`:

| 렌즈 | H | 선명 하한 (H/2) | 0.4m 디포커스 |
|---|---|---|---|
| RealSense f=1.93 f/2.0 | 414mm | 207mm | ~1.5px ✅ |
| **ZED X 2.2mm f/2.2** | 489mm | **244mm** | **0.44px ✅** |
| ZED X 4.6mm f/2.0 | 4,702mm | 2,351mm | **8.1px ❌** |

→ **ZED X 2.2mm 은 0.27m 부터 무한대까지 선명**하다. 4.6mm 만 근접 불가이고, 이유는 Min-Z 가 아니라 **초점**이다.

## 2. 유도값

`fx = (W/2)/tan(HFOV/2)` (L/R 이미저 HFOV, 정류 핀홀). ZED X 는 **실측 캘리브레이션**을 쓴다.

| 카메라 (해상도) | `fx` | B mm | **`fx·B`** | mm/px @0.4m | mm/px @1.0m | 선명 하한 |
|---|---|---|---|---|---|---|
| D405 (1280×720) | 640 | 18 | 11,520 | 0.625 | 1.562 | 207mm |
| D435 (1280×720) | 640 | 50 | 32,000 | 0.625 | 1.562 | 207mm |
| D455 (1280×720) | 640 | 95 | 60,800 | 0.625 | 1.562 | 207mm |
| **★ ZED X 2.2mm (1920×1200)** | **727.575** ← 실측 | **120.202** | **87,455** | **0.550** | **1.374** | **244mm** |
| ZED X 4.6mm (1920×1200) | ~1297 | 120 | ~155,600 | 0.308 | 0.771 | 2,351mm ❌ |
| *(참고) 옛 sim 런* | 1201 | 120 | 144,136 | 0.333 | 0.833 | — |

**5mm 예산 상한 거리** `Z = √(5·fx·B/σ_disp)`:

| σ_disp | D405 | D435 | D455 | **ZED X 2.2mm** |
|---|---|---|---|---|
| 0.35px (벤더 스펙 함의) | 0.41m | 0.68m | 0.93m | **1.12m** |
| 0.9px (실측 상한) | 0.25m | 0.42m | 0.58m | **0.70m** |

⚠️ **`σ_disp` 는 카메라 간 전이되지 않는다** — 시차가 큰 카메라일수록 절대 px 오차가 크다
(`RESULTS.md § sim D435 재현 실험`). 위 표는 **상대 비교용**이다.
⚠️ 기존 `RESULTS.md §5` 표의 D435/D455 `fx 674`(depth FOV 87° 기준)를 여기서는 **이미저 FOV 90° 기준 640**
으로 쓴다. 5% 차이이고 어떤 결론도 바뀌지 않는다.

★ **ZED X 실측이 예측을 검증했다** — 데이터시트 `<0.8% @2m` 이 함의하는 σ_disp ≈ 0.35px 와
sim 실측 0.32~0.95px 이 정합한다(`RESULTS.md §34-1`).

## 3. 판정

### 3.1 채택 — **ZED X 2.2mm 단독**

| 축 | ZED X 2.2mm | D455 | D435 | D405 |
|---|---|---|---|---|
| **`fx·B`** | **87,455** | 60,800 | 32,000 | 11,520 |
| 스테레오 쌍 | **RGB** | 모노 + 별개 컬러 | 모노 + 별개 **롤링** 컬러 | **RGB** |
| 화소수 | **2.30 MP** | 1.02 MP | 1.02 MP | 1.02 MP |
| mm/px @0.4m | **0.550** | 0.625 | 0.625 | 0.625 |
| 0.35m 선명 | ✅ | ✅ | ✅ | ✅ |
| IR 프로젝터 | 없음 🔴 | **있음** | **있음** | 없음 |
| 보호등급 | **IP67** | — | — | — |
| 인터페이스 | GMSL2 (Jetson 필요) | USB-C | USB-C | USB-C |

**전 항목 우위이고 유일한 열세는 IR 프로젝터 부재다.** 그리고 광각(HFOV 105.7°)이라
**FOUP 전체가 0.45m 부터 프레임에 들어가** 원거리 단계를 **0.55~0.70m 로 당길 수 있다**
→ σ_Z 가 거리 제곱으로 줄어 `fx·B` 0.607× 손해를 되갚는다(§34-3, 실측 t 1.78배 개선).

**순위**: ① ZED X 2.2mm ② D455(프로젝터가 필요할 때만) ③ D405(불필요 — 근접도 ZED X 가 낫다)
④ D435(모든 항목에서 D455 에 열세).

### 3.2 광각의 대가와 그 해법 — **거리로 되찾는다**

| | flange 등가 지름 | 정합기 자체 바닥 R | 정합 이득 |
|---|---|---|---|
| 옛 sim fx1200@1280×720 @0.35~0.50m | 413px | 0.188° | ×1.78 |
| ZED X @1920×1200 **@0.35~0.45m** | **264px** | 0.384° | **×0.82 (해롭다)** |
| **ZED X @1920×1200 @0.22~0.30m** | **419px** | **0.220°** | **×1.66** |
| ZED X @1920×1200 @0.18~0.24m | 523px | 0.163° | (FP 가 무너져 무의미) |

**해상도가 2.25배여도 광각이라 같은 거리에서 물체는 픽셀로 1.56배 작아진다** — 지배 변수는
«화소 수» 가 아니라 **«물체가 차지하는 픽셀 수»** 다(교훈 #70). **레버는 `fx` 와 `Z` 뿐이고 `fx` 는
렌즈로 고정이므로 `Z` 를 줄여 되찾는다**(교훈 #73). 상세: `RESULTS.md §34-4·§34-9`.

### 3.3 배포 구성 — **단일 시점** (`RESULTS.md §34-11`)

```
[A] 위치 인지 시 (권장·기본)
    근접 0.22~0.30m → SAM3 flange exemplar → FP --no-stage2 → 테두리 정합 --outer-only → 게이트 1.5°
    R 0.273° / t 0.770mm / 119-120 · 계산 2.6s · 로봇 이동 0회 · hand-eye 불필요
[B] 위치 미인지
    원거리 0.55~0.70m → SAM3 full exemplar(n-refs 3) → FP --no-stage2 → 사전위치 ±100mm 가드
      → (접근) → [A]                                        계산 5.4s · 이동 1회
```
★ **근접 거리에 최적점이 있다 — 0.22~0.30m.** 더 당기면(0.18~0.24m) baseline 120mm 이 거리에 비해
커져 미중첩 25%·좌우 시선 33°·depth RMSE 3.4→16.8mm 로 **FP 가 다시 뒤집힌다**(`RESULTS.md §34-9`).
⚠️ 0.25m 접근이 **로봇 동선상 가능한지 미확인** — ZED X 는 163.4×31.8×36.7mm 다.

⚠️ **FP 는 `--input-scale` 을 줄여야 한다** — 1920×1200 에서 OOM 난다. §22 근거로 정보 손실 없음.
★ **상한은 `0.75`** — `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`(`envs/env.sh` 가 상설로 건다)가
있어야 하고, 없으면 몇 프레임 뒤 OOM 이다. `1.0` 은 여전히 불가. → `RESULTS.md §38-4`.
⚠️ 다중시점 융합(R 0.274/t 0.443)이 정확도로는 더 낫지만 **계산 ~20초 + 이동 5회**라 10초 제약에 탈락.

## 4. 시스템 구성 (확정)

```
Jetson NX + ZED Link  ──rectified L/R PNG(무손실)──▶  RTX 5090 워크스테이션
  · pyzed 로 캡처만                                     · stereo / segment / pose / fuse
  · DEPTH_MODE.NONE (SDK depth 안 씀)                   · frame_XXXX/{left,right}.png + cam.json
```
- **pose 1회 = 6프레임**(원거리 5 + 근접 1) = 약 83MB → **대역폭 무관**. 영상 스트리밍이 아니다.
- 🔴 **rectified 만 소비한다.** raw 는 `k1 0.543` 의 강한 배럴이고, rectified 는 `disto` 가 **전부 0**
  이라 우리 sim 의 핀홀 모델과 동형이다.
- 🔴 **JPEG 금지** — 서브픽셀 기울기 정합이 압축 아티팩트를 먹는다. PNG 무손실 · BGR8(알파 제거).
- 해상도 모드는 **HD1200 고정**. 바꾸면 캘리브레이션·SAM3 참조가 전부 무효다 —
  `capture_real --cam <프로파일>` 이 이 사고를 **non-zero 종료로** 잡는다.
- 캡처 스테이지: **`spatial_vision.stages.capture_real`** (Jetson 에서 실행).
  이미 찍어 둔 이미지가 있으면 `tools/make_frame_from_zed.py`.
